First push of a new branch

❌ Without -u

$ git checkout -b feature/login Switched to a new branch 'feature/login' $ # ... commit something ... $ git push fatal: The current branch feature/login has no upstream branch. To push the current branch and set the remote as upstream, use: git push --set-upstream origin feature/login To have this happen automatically for branches without a tracking upstream, see 'push.autoSetupRemote' in 'git help config'.

✓ With -u

$ git checkout -b feature/login Switched to a new branch 'feature/login' $ # ... commit something ... $ git push -u origin feature/login Enumerating objects: 5, done. Counting objects: 100% (5/5), done. ... To github.com:MUKE-coder/gritlearn.git * [new branch] feature/login -> feature/login branch 'feature/login' set up to track 'origin/feature/login'. $ git push # no -u needed anymore Everything up-to-date

What does "tracking" mean, concretely?

After -u, Git writes this to .git/config:

[branch "feature/login"]
  remote = origin
  merge = refs/heads/feature/login

That's the "tracking" relationship — your local branch knows which remote branch to push to and pull from. git status can then say things like:

$ git status On branch feature/login Your branch is ahead of 'origin/feature/login' by 2 commits. (use "git push" to publish your local commits)

For every subsequent branch, you need -u again on its first push — Git doesn't auto-track new branches unless you set push.autoSetupRemote = true in your global config:

$ git config --global push.autoSetupRemote true # Now every 'git push' from a new branch auto-sets the upstream.
