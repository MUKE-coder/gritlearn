A realistic commit walkthrough

This mimics a real session — create a file, commit, edit, commit again, view history. Each step shows what to type and what to expect.

1 Initialize and write the first file

mkdir notes && cd notes && git init
Initialized empty Git repository in ~/notes/.git/
echo "# My Notes" > README.md
README.md exists in the working directory. Git doesn't know about it yet.

2 Check status

git status
On branch main No commits yet Untracked files: (use "git add <file>..." to include in what will be committed) README.md
README is untracked — exists on disk, not in Git.

3 Add and commit

git add README.md
git status
On branch main Changes to be committed: new file: README.md
git commit -m "Add README"
[main (root-commit) a1b2c3d] Add README 1 file changed, 1 insertion(+) create mode 100644 README.md
First commit done. a1b2c3d is the short hash.

4 Edit the file

echo "Built with JEditor." >> README.md
git status
On branch main Changes not staged for commit: modified: README.md
The file is back to "modified" — Git sees it differs from the last commit.

5 See the diff before committing

git diff
diff --git a/README.md b/README.md index e69de29..f1234ab 100644 --- a/README.md +++ b/README.md @@ -1 +1,2 @@ # My Notes +Built with JEditor.
One line added. Always run git diff before committing to confirm you're shipping what you intended.

6 Commit and view history

git add . && git commit -m "Add subtitle"
[main e5f6a7b] Add subtitle 1 file changed, 1 insertion(+)
git log --oneline
e5f6a7b Add subtitle a1b2c3d Add README
Two commits. Newest first. Each shows the short hash and the message.
