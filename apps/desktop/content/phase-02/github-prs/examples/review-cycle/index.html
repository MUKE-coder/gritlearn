The review loop in 6 steps

Same PR, two people. Author commits and pushes; reviewer reads and comments; loop until approved.

A
author
step 1 Open the PR Push branch feature/dark-mode. Open PR titled "Add dark mode toggle." Description: what + why + test plan. Request review from lin.
PR exists. CI starts running. Reviewer gets a notification.
L
reviewer
step 2 Read the diff, leave comments Opens "Files changed" tab. Reads navbar.tsx, theme-toggle.tsx, globals.css. Leaves two comments:
· "What happens if localStorage is full?"
· "Suggestion: prefer `useEffect` over inline script." Submits as Request changes.
Merge button is now blocked until reviewer re-approves.
A
author
step 3 Address feedback Add try/catch around localStorage. For the inline-script question, reply: "The script avoids the flash of wrong theme before useEffect runs — that's why we kept it." Push two new commits. The PR auto-updates.
Some feedback addressed in code; some pushed back on with explanation. Both are valid.
L
reviewer
step 4 Re-review just the new commits Uses "Compare changes since your last review" to see only the diff added since step 2. Reads the try/catch. Reads the inline-script reply, agrees with the reasoning. Resolves both conversations.
Iterative review is fast — only the new changes need re-reading.
L
reviewer
step 5 Approve Clicks "Review changes" → "Approve" → "LGTM." The PR now shows a green checkmark next to lin's name. CI is also green. Merge button turns active.
Author can now merge. (On some teams, only the author merges; on others, the approver does.)
A
author
step 6 Merge + cleanup Click "Squash and merge". PR closes. GitHub prompts to delete the branch — delete it. Locally: git checkout main && git pull && git branch -d feature/dark-mode.
Feature ships to main. The next deploy will include it.
