Resolving a real conflict — six steps

1 Run the merge — see the conflict

$ git checkout main Switched to branch 'main' $ git merge feature/formal Auto-merging greet.js CONFLICT (content): Merge conflict in greet.js Automatic merge failed; fix conflicts and then commit the result.
Git stopped mid-merge. greet.js now has conflict markers inside it.

2 Confirm which files conflicted

$ git status On branch main You have unmerged paths. (fix conflicts and run "git commit") Unmerged paths: (use "git add <file>..." to mark resolution) both modified: greet.js
One file conflicted. "both modified" means each branch changed it.

3 Open the file — read both versions

$ cat greet.js
function greet(name) { <<<<<<< HEAD return "Hi, " + name + "!"; ======= return "Hello, " + name + "."; >>>>>>> feature/formal }
Top section = main's version. Bottom section = feature's version. You decide.

3 Edit the file — pick a resolution

Delete all four marker lines and leave only the version you want. For this demo, we'll combine both:
function greet(name) { return "Hello, " + name + "."; }
Saved.

5 Mark resolved + commit

$ git add greet.js $ git status On branch main All conflicts fixed but you are still merging. (use "git commit" to conclude merge) $ git commit # Git pre-fills the message: # Merge branch 'feature/formal' [main 7f3a2c1] Merge branch 'feature/formal'
The merge is complete. A merge commit (7f3a2c1) ties the two timelines together.

6 Verify with the log graph

$ git log --oneline --graph -5 * 7f3a2c1 Merge branch 'feature/formal' |\ | * 8b2e1f0 feat: use formal greeting * | c1d4e7a feat: use casual greeting |/ * a1b2c3d init: add greeting
The graph shows both branches merging back into one. The conflict resolution is captured in the merge commit.
