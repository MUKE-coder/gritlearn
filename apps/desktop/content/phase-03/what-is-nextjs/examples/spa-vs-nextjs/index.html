The first response — same UI, very different HTML

Your browser is opening / on each site. Same page in both cases. Here's what the server sends back as the first response.

spa-app.example.com/
Network: 1 HTML (200 bytes) + bundle.js (210 KB) — 2.4s to first content
<!DOCTYPE html>
<html>
  <head>
    <title>App</title>
    <script src="/bundle.js" defer></script>
  </head>
  <body>
    <div id="root"></div>
    <!-- nothing else.
         the browser will:
         1. parse this empty body
         2. download bundle.js (210KB on 3G = 4 seconds)
         3. run the JS
         4. mount React, fetch the user's data
         5. only NOW render the page -->
  </body>
</html>
What the user sees first: a blank white page for ~2-4 seconds (longer on mobile).
SEO: Google's crawler has to execute JS to see content — flaky, slow.
next-app.example.com/
Network: 1 HTML (12 KB) + JS hydration (loads after first paint) — 180ms to first content
<!DOCTYPE html>
<html>
  <head>
    <title>App</title>
  </head>
  <body>
    <nav>
      <a href="/about">About</a>
      <a href="/blog">Blog</a>
    </nav>
    <main>
      <h1>Welcome, Ada Lovelace</h1>
      <p>You have 3 unread notifications.</p>
      <ul>
        <li>Sam liked your post</li>
        <li>Lin commented...</li>
        <li>New release: v0.2.0</li>
      </ul>
    </main>
    <script src="/_next/...js" defer></script>
  </body>
</html>
What the user sees first: the actual page — title, nav, content — in milliseconds.
SEO: Google sees the HTML on the first request. No JS execution needed.
Hydration: the JS still loads after; it "attaches" interactive behavior on top of the HTML.

The difference is real, not marketing

Open jbeditor.com or any Next.js site in your devtools. Network tab. Reload. Click the first request (type "document"). Look at the response body. You'll see HTML with your content already in it — not an empty SPA shell.
