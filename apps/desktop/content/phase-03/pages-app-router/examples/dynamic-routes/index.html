Three dynamic-route flavors

Brackets and parentheses in folder names do different jobs. Here's each one with its rule, a real example, and what shows up in your component.

[slug] — single dynamic segment

One folder name in brackets captures exactly one URL segment as a string.

FolderExample URLparams
app/blog/[slug]/page.tsx /blog/hello-world { slug: "hello-world" }
app/users/[id]/posts/[postId]/page.tsx /users/47/posts/9 { id: "47", postId: "9" } 
// app/blog/[slug]/page.tsx
export default function BlogPost({
  params,
}: { params: { slug: string } }) {
  return <h1>Post: {params.slug}</h1>;
}

[...path] — catch-all segment

Three dots inside the brackets capture one or more segments as an array. Used for docs sites, file browsers, anywhere URL depth is variable.

FolderExample URLparams
app/docs/[...path]/page.tsx /docs/a { path: ["a"] }
app/docs/[...path]/page.tsx /docs/api/users/create { path: ["api", "users", "create"] }
Does not match /docs (zero segments). For that, use [[...path]] (double brackets — optional catch-all).

(name) — route group (URL-less)

Parentheses around a folder name don't add to the URL. Used to share a layout across pages that should stay at top-level URLs.

FolderURLNote
app/(marketing)/pricing/page.tsx /pricing "(marketing)" is invisible in the URL
app/(marketing)/careers/page.tsx /careers Shares the marketing layout
app/(dashboard)/settings/page.tsx /settings Different layout from the marketing group
The classic SaaS pattern: (marketing)/ for the public site with a public nav; (app)/ for the authenticated UI with a sidebar.
