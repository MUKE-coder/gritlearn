The "server components as children" pattern

Same goal: an interactive filter wrapping an expensive list. Left column gets it wrong; right column gets it right.

❌ Before — client imports server

// app/page.tsx
server 
import { Filters } from "@/components/Filters";

export default async function Page() {
  return <Filters />;
}
// components/Filters.tsx
client 
"use client";
import { useState } from "react";
import { ExpensiveList } from "./ExpensiveList";
// ❌ importing the server component here
//    forces it to become a client component too

export function Filters() {
  const [filter, setFilter] = useState("all");
  return (
    <div>
      <FilterControls value={filter} onChange={setFilter} />
      <ExpensiveList filter={filter} /> {/* now ships as client JS */}
    </div>
  );
}
Result: The 500-item ExpensiveList ships as JavaScript (~50 KB). Its rendering, formatters, date parsers all run in the browser. Page is slow to hydrate. Lighthouse bundle-size warning.

✓ After — server passed as children

// app/page.tsx
server 
import { Filters } from "@/components/Filters";
import { ExpensiveList } from "@/components/ExpensiveList";
// ✓ both imported HERE (server context)

export default async function Page() {
  const items = await getExpensiveData();
  return (
    <Filters>
      <ExpensiveList items={items} /> {/* server-rendered */}
    </Filters>
  );
}
// components/Filters.tsx
client 
"use client";
import { useState } from "react";
// ✓ no import of ExpensiveList — receives it as children

export function Filters({ children }: { children: React.ReactNode }) {
  const [filter, setFilter] = useState("all");
  return (
    <div>
      <FilterControls value={filter} onChange={setFilter} />
      {children} {/* rendered on server, slotted in here */}
    </div>
  );
}
Result: ExpensiveList stays a server component. Its 50 KB doesn't ship as JS. The page sends finished HTML for the list + 200 bytes of client JS for the filter. Lightning-fast hydration.

Why this works

The rule: when a client component imports a server component, the server one gets bundled with it (and becomes client). When a client component receives a server component as children (a value), no import happens — the framework rendered it elsewhere and just slots it into the JSX.

The shape you'll write a hundred times in real apps: <ClientWrapper><ServerHeavyThing /></ClientWrapper>. Compose at the boundary; keep the heavy server work as children.
