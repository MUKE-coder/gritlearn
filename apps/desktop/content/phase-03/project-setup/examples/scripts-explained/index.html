The four daily scripts

Defined in package.json's scripts object. Each one runs a different Next.js command for a different stage of work.

pnpm dev

Starts a development server with hot reload. Edit a file, save, see the change in the browser instantly.

$ pnpm dev
▲ Next.js 14.2.0
  - Local:        http://localhost:3000
  - Environments: .env.local

✓ Ready in 1.2s
○ Compiling /...
✓ Compiled / in 142ms
When to use

Active development. Have it running all day, leave the browser tab open.

pnpm build

Builds a production bundle. Runs the TypeScript type-check, optimizes JS, generates static pages, writes .next/.

$ pnpm build
▲ Next.js 14.2.0

  Creating an optimized production build...
  Compiled successfully in 8.3s
  Running TypeScript ...
  Generating static pages (4/4)

Route (app)
┌ ○ /                    142 B   84.3 kB
├ ○ /about               147 B   84.3 kB
└ ƒ /api/users           0 B     0 B

✓ Build successful
When to use

Before pushing a big change. CI runs it on every PR. Vercel runs it on deploy. Catches type errors that dev doesn't.

pnpm start

Serves the production bundle locally (the output of pnpm build). Behaves like real production.

$ pnpm build && pnpm start
▲ Next.js 14.2.0
  - Local: http://localhost:3000

✓ Ready in 320ms
When to use

To verify production behavior locally before deploy. Some bugs only show in production builds (server components, ISR, edge runtime).

pnpm lint

Runs ESLint on the codebase. Flags style violations, unused variables, common mistakes.

$ pnpm lint
▲ Next.js 14.2.0

./app/page.tsx
  12:7  Error: 'name' is assigned but never used. (no-unused-vars)

✖ 1 error
When to use

Before committing. Some teams run pnpm lint as a pre-commit hook so it runs automatically.

One-liner you'll memorize: pnpm build && pnpm start — verifies a production build locally before pushing. Catches every "works in dev, breaks in production" bug.
