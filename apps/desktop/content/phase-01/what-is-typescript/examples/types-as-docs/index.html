Two ways to document a function

Both describe the same function. Only one of them stays honest as the code evolves.

1. JSDoc — the comment can lie

/**
 * Format a user's display name.
 * @param {Object} user - the user object
 * @param {string} user.name - their full name
 * @param {string} user.title - their job title    ← STALE
 * @returns {string} formatted display string
 */
function format(user) {
  return user.name;   // 'title' silently removed last sprint
}                     // …docstring never updated. Future you reads
                      // it, expects a title, gets a name. Bug.

2. TypeScript — the contract is enforced

type User = {
  name: string;
};

function format(user: User): string {
  return user.name;
}

format({ name: "Ada" });                  // ✓
format({ name: "Ada", title: "Dr" });     // ✗ Property 'title' does
                                          //   not exist on User.
format({});                               // ✗ Property 'name' is missing.

If someone later adds user.title back, the type forces them to update the User definition. The contract and the code can't drift apart — the build will refuse to ship a mismatch.
