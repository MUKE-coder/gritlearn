When to reach for what

Two reuse patterns for the same kind of UI element, side by side, with notes on when each fits.

Component (React / Vue / Astro)

// Card.tsx
export function Card({ title, body, footer }) {
  return (
    <div className="bg-white border border-gray-200
                    rounded-xl p-5 shadow-sm
                    hover:shadow-md transition-shadow">
      <h3 className="font-semibold mb-1">{title}</h3>
      <p className="text-sm text-gray-600">{body}</p>
      {footer && (
        <footer className="mt-3 pt-3 border-t
                           border-gray-100 text-xs">
          {footer}
        </footer>
      )}
    </div>
  );
}

Best when you have:

  • A component framework (React, Vue, Svelte, Astro)
  • Variation via props (title, icon, variant)
  • Behavior (onClick, hover state, animations)
  • Markup that's more than one element

@apply class (CMS templates, plain HTML)

/* tokens.css */
@layer components {
  .card {
    @apply bg-white border border-gray-200
           rounded-xl p-5 shadow-sm
           hover:shadow-md transition-shadow;
  }
  .card-title {
    @apply font-semibold mb-1;
  }
  .card-body {
    @apply text-sm text-gray-600;
  }
}

<!-- in your CMS template -->
<div class="card">
  <h3 class="card-title">Title</h3>
  <p class="card-body">Body</p>
</div>

Best when you have:

  • No JS component framework (raw HTML, CMS templates)
  • A long-form content class (.prose, .article)
  • Cross-framework tokens (used in React app AND in a static page)
  • Genuinely "the class name IS the interface"

In a modern React/Next.js app, the component is the answer 90% of the time. Reach for @apply only when the class name itself is the interface you want.
